## 공통 화면

- 상단 로고·아이콘 5개·사용자명, 왼쪽 메뉴와 선택 배경, 작업 탭 제목/닫기/+가 모두 정상적으로 보인다.
- 환율 영역은 ‘환율 정보를 불러올 수 없습니다’라는 실제 실패 상태다. 화면은 깨지지 않았으나 환율 기능 정상 데이터 표시를 확인한 것이 아니다.
- 보조문구는 회색 11~12px 크기로 촘촘하다. 특히 사이드바 맨 아래 단축키 설명과 대시보드 보조 설명은 시각적 대비가 약하다. 대비 측정으로 WCAG 실패를 확정한 것은 아니다.
- 콘텐츠 시작선이 페이지마다 다르다: 대시보드 약 x231/y135, 운영현황 x252/y150, 항공 x252/y178, 메일 x454/y150, 설정 x252/y150. 메일 중앙 폭 제한은 의도된 디자인일 수 있으나 제목 위치/상단 간격 통일이 완성도를 높인다.
- 캡처 6개에서 데스크톱 가로 잘림, 버튼 중첩, 깨진 아이콘, 폰트 누락, 입력창 잘림은 발견하지 못했다.

## 코드 근거와 연결되는 실화면 발견

1. 대시보드 실제 ‘+22건 더보기’ 노출 + TodayBookingsSection.tsx에서 `<p>` 확인: 기능 없는 더보기 표시가 사용자 동작을 유도함.
2. 사용자 ‘프로필 설정’은 `/settings`로 연결 + 실제 설정 화면은 직원 권한 관리: 개인 프로필 편집 화면과 불일치. 사용자 메뉴 캡처·클릭 검증은 아직 필요.
3. 메일 화면은 미연결 안내만 존재. 실화면에서 수신/발신/첨부 기능이 없다는 안내를 확인함.

## 추가 검토 — 차트 하단·항공 오류·자동화·직접 URL

- `24-dashboard-bottom`: 진행률·출발예정 카드·차트 2개 배치 정상. 차트 hover 툴팁이 `value : 0`이라는 영문 내부 필드명을 표시한다. `예약 금액: 0원` 같은 사용자 문구로 바꾸는 것이 좋다. 회색 세로 영역은 hover cursor로 보이며 실제 금액 막대와 구별되어야 한다.
- `25-stats-quarter`, `26-stats-year`: 기간 선택 강조와 x축의 분기/연도 전환 정상. 기존 담당자 건수 차트의 소수 눈금/밀집 문제는 동일하다.
- `27-stats-table-bottom`: 긴 표를 아래로 스크롤하면 표 머리글이 사라진다. 숫자 열 의미를 계속 확인하려면 sticky 헤더가 유용하다. 실제 표 행/글자는 잘리지 않는다.
- `28-flights-PUS`, `29-flights-retry`: PUS 선택 후 갱신 실패의 빨간 오류 패널이 온전히 표시된다. 재시도 후에도 같은 오류 화면이다. 화면 표시 검증은 됐으나 실제 스케줄 조회 성공은 미확인이다.
- `30-flow`: 자동화 실행 불가/메일 발송 불가/외부 연동 불가 안내를 실화면에서 확인. ‘예약관리에서 직접 처리’는 파란색이지만 코드상 링크가 아닌 dd 텍스트다. 클릭 가능한 링크로 오인할 가능성이 있다.
- `33-legacy-dashboard`: 실제로 상단 헤더·사이드바·작업 탭이 전부 없고 대시보드만 브라우저 좌측 맨 위부터 표시된다. 공통 탐색이 사라지는 직접 URL 문제가 확정되었다.

`34-legacy-reservations`, `35-icon-test`, `36-workspace-direct`도 추가로 직접 확인했다(총 36개). `/reservations`도 헤더·사이드바·작업 탭 없이 자체 예약관리 화면만 표시된다. `/icon-test`는 운영 빌드에 영문 개발 테스트 화면과 Debug Information이 그대로 노출된다(직접 URL, 기본 메뉴에서는 안 보임). `/workspace` 직접 URL은 공통 프레임 안에서 정상 표시된다.

남은 확인: 모바일 직원 모달/사용자 메뉴, 설정 표 오른쪽 스크롤 후 작업 도달, 성공 항공표(가능한 경우).

## 항공편 저장 자료로 UI 상태 검토 (74~78)

이 5개는 실시간 서버 응답 성공이 아니다. 2025-07-29 저장된 PUS 스냅샷을 route.fulfill로 전달한 **UI fixture**이며, 현재 운항 정보 검증과 분리한다. 총 직접 검토 캡처는 41개다.

- `74-flights-snapshot-desktop`: PUS→NRT, 항공사 5행/항공편 6개와 월~일 7열이 온전히 표시된다. 항공사·시간·편명 계층은 명확하고 겹침이 없다. 오래된 자료 경고가 표 위에 표시된다. 목적지 표기가 `NRT - NRT`로 중복되어 공항명(나리타)을 알아보기 어렵다.
- `75-flights-snapshot-mobile-left`: 모바일 표는 가로 스크롤형이며 항공사·월·화가 보인다. 오른쪽 열은 잘려 보이는 것이 의도된 스크롤 영역이다. 좌우 스크롤 안내가 없어 사용자가 발견하기 어렵다.
- `76-flights-snapshot-mobile-right`: 오른쪽 끝 스크롤로 금·토·일 열이 나타나 도달 가능한 것을 확인했다. 항공사 열이 함께 사라져 어떤 항공사 시간인지 판단하기 어렵다. 첫 열 고정이 필요하다.
- `77-flights-stale-after-error`: 새로고침 실패와 이전 자료 유지 안내가 빨간 박스로 표시되고, 오래된 자료 기준/표도 유지된다. 오류문구가 모바일에서 세 줄 이상으로 정상 줄바꿈하며 겹침이 없다.
- `78-flights-empty-fixture`: USN 선택, 도착 비활성, 기준시점/오래된 자료 안내, ‘제공된 자료에 운항 노선이 없습니다’ 표시 정상.

이 확인으로 시간표의 표시와 모바일 좌우 도달, stale/실패/빈 응답 UI는 검토했으나 실제 항공 서버 연결은 여전히 실패 상태다.
