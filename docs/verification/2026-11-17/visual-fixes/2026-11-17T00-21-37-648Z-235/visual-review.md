# 메뉴 화면 실물 판독 기록

2026-11-17. 이 폴더의 PNG **43장을 모두 `view_image`로 열어 직접 판독**하고 `report.json`의 geometry / bottomGeometry 후보와 대조했다. 대상은 **12개 메뉴 × 3개 폭(1440 / 800 / 390px) = 36개 화면 상태**다. 36개 메뉴를 각각 3회 확인한 것은 아니다.

이번 초기 화면 캡처 범위에서 **새로 확인된 심각한 겹침, 주요 조작부 잘림, 접근을 막는 레이아웃 결함은 없었다.** 이 문장은 제품 전체 기능의 완료 판정이나 자동 시각 PASS를 뜻하지 않는다. 캡처에 없는 편집 폼·저장·실제 메시지 대화·외부 서비스 성공은 별도 기능 검증 대상이다.

## Geometry 후보 19건 판독

후보는 전부 `settings`의 `HORIZONTAL_ACTION_CLIPPING`이다. 페이지 전체가 가로로 넘친 사례나 별도의 도구모음 잘림 후보는 없었다.

| 화면 | 후보 | 실제 구조와 판단 |
|---|---:|---|
| 800px 설정 | 비활성화 5, 재활성화 2 = 7건 | 직원 표의 `clientWidth=504`, `scrollWidth=567`, `overflowX=auto`. 오른쪽 작업 열이 스크롤 시작 위치에서 밖에 있는 상황과 일치한다. 제목/검색/직원 추가/새로고침은 가려지지 않는다. |
| 390px 설정 | 편집 5, 비활성화 5, 재활성화 2 = 12건 | 직원 표의 `clientWidth=339`, `scrollWidth=567`, `overflowX=auto`. 가로 스크롤 안내가 실제 화면에 보인다. 표 내부 우측 열이 아직 보이지 않는 상태로, 스크롤할 수 없는 잘림이라는 증거는 없다. |

19건을 자동으로 결함 또는 PASS로 바꾸지 않았다. 이 43장 묶음에는 설정 표의 우측 끝 캡처나 작업 버튼 클릭 장면이 없으므로 **우측 이동 후 실행 가능 여부는 별도 핵심 동작 캡처/검증 기록과 함께 판단해야 한다.** 예약 목록(940px), 통계(650px), 거래 내역(590px) 표의 오른쪽 열도 같은 이유로 의도된 내부 스크롤과 구분했다. 캘린더/대시보드의 하단 또는 상단 바깥 내용은 세로 스크롤 위치에 따른 것이며, 스크린리더 전용 `sr-only` 요소의 1px overflow도 시각적 잘림으로 세지 않았다.

수집 로그상 36개 경로는 모두 일치했고 pageErrors/failures/dialogs는 비어 있다. 이는 수집 중 관찰된 오류가 없었다는 보조 근거일 뿐, 이미지 판독이나 기능 검증을 대신하지 않는다.

## 이번 검토에서 유지하는 한계

- 메일 조회·첨부 다운로드·발송 연동은 아직 구현/연결되지 않았다. 세 폭 모두 이를 명시적으로 안내한다.
- Flow는 기존 미구현 범위이며 이번 12개 메뉴 묶음에 포함되지 않는다.
- 외부 항공 데이터의 기존 503 문제는 해결되었다고 판단하지 않는다. 이번 항공 세 장은 선택 전 UI만 보여 준다. 저장 스냅샷의 공항명·요일표·오래된 자료 경고·갱신 실패 보존은 별도 핵심 캡처에서 검토해야 한다.
- 데스크톱 상단의 환율 불러오기 실패 문구는 기존 외부 서비스 제한으로 남아 있다.
- 편집 폼, 저장/승인/메시지 전송, 각 내부 스크롤의 끝까지 이동 및 키보드 접근은 정지 이미지 43장만으로 검증 완료를 주장하지 않는다.
