# Entrip v2 실행 안내

이 변경은 `b` 개발 브랜치를 기준으로 합니다. 기존 파란색·흰색 화면을 유지하며 예약, 작업 탭, 계좌·입출금·결재, 메신저, 직원 관리와 통계를 v2 API/DB에 연결합니다.

## Windows PC 한 대를 사내 서버로 사용하기

1. 호스트 PC의 로컬 폴더에 Windows LAN ZIP 전체를 풀고 **`run.bat`**을 더블클릭합니다. 처음에는 인터넷 연결과 Linux 컨테이너를 지원하는 Docker Desktop이 필요합니다. Docker가 없으면 실행기가 설치를 안내합니다. Windows가 재부팅을 요청하면 재부팅 후 같은 폴더의 `run.bat`을 다시 실행합니다.
2. 최초 빌드와 DB 초기화가 끝나면 호스트에서 로그인 화면이 열립니다. 콘솔에 나온 `.entrip-lan\first-login.txt`를 열어 회사·이메일·초기 비밀번호를 확인합니다. 호스트 관리자가 **설정 → 직원 추가**에서 직원별 계정을 만듭니다.
3. 직원에게 콘솔의 **같은 네트워크에서 접속** 주소와 직원 계정을 전달합니다. 예를 들어 호스트에 `http://192.168.0.25:3000`이 표시되면 직원은 같은 유선망이나 Wi-Fi에서 그 주소를 브라우저로 엽니다. 호스트 관리자 비밀번호와 `.entrip-lan` 폴더는 호스트에 보관합니다.

실행 창을 닫아도 서비스는 Docker에서 계속 동작합니다. 직원은 호스트 PC와 Docker가 켜진 동안 같은 LAN에서 접속할 수 있습니다. `run.bat status`로 상태를 확인하고 `run.bat stop`으로 중지합니다. 업무 DB는 호스트의 **`.entrip-lan\data\entrip.sqlite`**에 저장됩니다. 업그레이드할 때 기존 설치 폴더와 그 안의 `.entrip-lan`을 유지하세요.

다른 PC에서만 연결이 안 되면 호스트가 표시한 **현재 IP와 포트**, Windows 회사/개인 네트워크 프로필, 방화벽 권한, 게스트 Wi-Fi의 기기 간 격리 설정을 확인합니다. IP가 바뀌면 `run.bat`을 다시 실행하고 새 주소를 공유합니다. 기본 포트 3000이 사용 중이면 호스트의 `.entrip-lan\server.env`에서 `ENTRIP_LAN_PORT`를 변경하고 다시 실행합니다. 이 LAN 구성은 HTTP를 사용하므로 신뢰하는 내부망에서 사용합니다. 인터넷 공개용 TLS 구성은 [운영 안내](PRODUCTION_V2_RUNTIME.md)를 따릅니다.

## 기존 예약을 유지하며 업데이트

1. 이전 버전을 사용하던 호스트에서 `run.bat stop`을 실행합니다.
2. 새 ZIP을 **기존 설치 폴더**에 덮어 풉니다. 기존 `.entrip-lan`에는 관리자 설정과 데이터가 있습니다. 이전 PostgreSQL 배포를 사용했다면 Docker의 기존 데이터 볼륨도 보존합니다.
3. 같은 폴더의 `run.bat`을 실행합니다. 실행기는 이전 PostgreSQL 볼륨을 찾아 일관된 시점의 데이터를 임시 SQLite 파일로 옮깁니다. 업무 테이블의 행과 값, 관계를 대조한 뒤 새 DB를 사용합니다. 검증에 실패하면 이전을 중단하고 원본 볼륨을 보존합니다.
4. 기존 관리자 계정으로 로그인해 직원·예약·수배·정산을 확인합니다. 그 뒤 `run.bat backup`으로 이번 상태를 즉시 보관할 수 있습니다.

## 자동 백업과 복구

호스트는 매일 **한국시간 08:00, 12:00, 18:00**에 예약·정산·직원·변경 이력을 함께 백업합니다. 서비스가 켜진 상태에서 진행 중인 쓰기와 일관된 SQLite 스냅샷을 `.entrip-lan\backups`에 만듭니다. 호스트가 꺼져 예약 시각을 넘기면, 다음 기동 때 가장 최근에 놓친 시점에 대응하는 백업을 **기동 당시 데이터**로 한 번 만듭니다. 생성된 백업은 30일간 보존합니다.

| 호스트 설치 폴더에서 실행 | 용도 |
| --- | --- |
| `run.bat backup` | 현재 상태를 수동 백업 |
| `run.bat backups` | 복구 가능한 백업 파일명과 생성 시각 확인 |
| `run.bat restore <백업파일명>` | 해당 시점으로 복구. 확인 후 쓰기 서비스를 잠시 중지하고 현재 DB도 별도로 보존 |

복구 파일명은 목록에 표시된 이름을 그대로 사용합니다. 복구하면 선택한 백업에 포함된 예약과 직원 비밀번호가 그 시점으로 돌아갑니다. 호스트 고장에도 대비하려면 완료된 스냅샷을 다른 저장장치에도 복사해 두세요. 운영 중인 DB 파일을 단독으로 복사하면 WAL에 있는 최신 쓰기가 빠질 수 있습니다.

교체 PC에서 복원할 때는 새 설치를 한 번 실행한 뒤, 기존 백업 파일을 새 설치의 `.entrip-lan\backups`에 넣고 `run.bat restore <백업파일명> -ReplaceInstallation`을 실행합니다. 복원 후에는 백업 당시의 직원 계정으로 로그인합니다. 백업에는 예약·고객 정보와 직원 계정이 함께 들어 있으므로 호스트 관리자용으로 보관하세요.

## DB 구조와 향후 PC 동기화

현재 같은 여행사의 직원은 브라우저를 통해 한 호스트의 SQLite를 사용합니다. 다른 호스트에서 독립적으로 새로 설치하면 별도의 DB와 기기 식별자가 생깁니다. PC별 오프라인 편집, 자동 발견, 기기 사이 변경 전송·병합은 후속 단계입니다.

- 기존 예약번호·내부 ID·연결 수배와 정산을 유지하면서 여행사, 기기, 업무 레코드에 고유 식별자를 부여합니다.
- 예약·직원·계좌·수배·정산·메시지 등 업무 데이터가 바뀌면 같은 DB 트랜잭션에서 변경 순번, 직전 변경 ID, 수정 차수, 변경·삭제 시각을 기록합니다. 저장에 실패한 작업은 이력에도 남지 않습니다.
- 같은 예약을 두 직원이 동시에 수정하면 기존 예약 버전을 대조합니다. 나중에 저장한 직원은 변경된 예약을 다시 조회할 수 있습니다. DB 복구 후에는 이전 동기화 커서를 재사용하지 않도록 변경 흐름의 ID를 새로 만듭니다.

## 개발용 로컬 실행

Node.js 22 이상, Corepack, PostgreSQL이 필요합니다. 프로젝트 루트에 `.env`를 만들고 접근 가능한 DB 주소를 지정합니다.

```dotenv
DATABASE_URL=postgresql://entrip:YOUR_PASSWORD@127.0.0.1:5432/entrip
```

Windows는 `START_ENTRIP.bat`, macOS/Linux는 `bash START_ENTRIP.sh`를 실행합니다. 패키지 설치 → v2 클라이언트 생성 → 보존형 DB 마이그레이션 → 빈 DB에만 데모 데이터 입력 → API 4002/웹 3000 실행 순서입니다. 웹 주소는 http://localhost:3000 입니다. 최초 화면에서 회사와 역할을 고릅니다.

데모 계정은 Entrip, J1, Startour, Happytravel의 관리자·매니저·직원이며 비밀번호는 `pass1234`입니다. 실제 업무 DB에 데모 계정을 배포하지 마세요. 기존 계정이 있으면 데모 입력을 건너뛰며 데이터를 삭제하지 않습니다. `RESET_DEMO_DATA=true`는 명시적인 개발용 전체 초기화 옵션입니다.

로컬 실행기의 JWT 서명 키는 `.env`에 없으면 실행마다 생성됩니다. 재시작 후 로그인이 풀리지 않게 하려면 `JWT_SECRET`, `JWT_REFRESH_SECRET`에 서로 다른 무작위 32자 이상의 값을 지정합니다. 운영은 [PRODUCTION_V2_RUNTIME.md](PRODUCTION_V2_RUNTIME.md)를 따릅니다.

## 주요 동작

- 월간·주간 캘린더와 목록에서 날짜나 예약을 선택합니다. 왼쪽 기본/고객 정보와 오른쪽 반복 여행 항목을 함께 저장합니다. 저장 후 인쇄와 변경 이력을 사용할 수 있습니다.
- Ctrl/Cmd+메뉴 클릭은 새 작업 탭을 엽니다. 탭별 입력과 편집 대상이 새로고침 후에도 유지됩니다. 회사나 사용자가 바뀌면 이전 작업 상태를 지웁니다.
- 계좌는 직원 계정과 별도입니다. 입출금을 등록하고 다른 관리자 또는 지정 결재자가 승인하면 잔액에 반영됩니다. 순차 결재는 지정된 순서를 따릅니다.
- 메신저에서 같은 회사 직원을 선택해 1:1 대화를 만들고 기존 방에 직원을 초대합니다. 메시지는 DB에 저장되며 실시간으로 전달됩니다.
- 관리자 설정에서 직원 추가·수정·비활성화·재활성화를 수행합니다.
- 항공편·환율은 실제 외부 서비스 설정이 필요합니다. 과거 스냅샷과 조회 실패를 구분해 표시합니다.

## 예약 입력과 페이지 인쇄

캘린더에서 날짜의 예약 등록 버튼을 누르면 해당 날짜로 **예약 정보**가 열립니다. 왼쪽에는 팀·고객·판매금액을 입력하고 오른쪽에서 항공·호텔·차량·기타 항목을 필요한 만큼 추가합니다. 좁은 화면에서는 기본정보 다음에 여행 항목이 이어집니다. 위쪽의 **취소**, **예약 저장**, **인쇄**를 사용하세요.

작업 탭 오른쪽의 **인쇄** 버튼이나 브라우저의 **Ctrl+P**로 현재 조회 화면을 출력합니다. 현재 기간·필터·페이지와 선택한 상세정보가 출력 범위를 결정합니다. 예약 편집 중에는 화면에 입력한 내용으로 예약서를 만듭니다. 저장 전 또는 수정 중인 예약서에는 그 상태가 표시됩니다. 예약창의 **인쇄**는 예약서 미리보기를 열고, 미리보기의 **인쇄**에서 프린터나 **PDF로 저장**을 선택합니다.

PDF 저장 시 배율은 기본값을 쓰고 브라우저의 **머리글과 바닥글**을 끄면 주소와 인쇄 시각을 덧붙이지 않고 양식을 저장할 수 있습니다. 계좌·결재 등 여러 페이지로 나뉜 조회는 현재 페이지에 표시된 범위를 출력합니다. 메신저에서는 현재 불러온 대화를 출력하며 **이전 메시지**를 불러오면 출력 범위도 늘어납니다.

## 검증 및 제한

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm run build
corepack pnpm exec jest --config jest.config.js --selectProjects @entrip/shared @entrip/ui @entrip/web --runInBand
```

API 테스트는 **별도의 `_test`로 끝나는 DB**에 `TEST_DATABASE_URL`을 설정하고 `bash scripts/test-db.prepare.sh`로 마이그레이션한 뒤 `corepack pnpm --filter @entrip/api test --runInBand`로 실행합니다. PostgreSQL 개발 DB와 SQLite 절대 경로(예: `file:/tmp/entrip_test`)를 모두 지원합니다. SQLite 테스트는 배포본의 변경 이력도 설치합니다. API 테스트는 해당 테스트 DB의 행을 삭제합니다.

실행 중인 앱의 실제 화면 검증 스크립트는 `scripts/verification/verify-*-ui.mjs`입니다. `BASE_URL`을 앱 주소로 지정합니다. 최종 실행 결과와 한계는 검증 문서를 참고하세요.

메일 OAuth/수신/발신, 자동화 실행, OCR·문서 연동은 미구현 상태를 명시합니다. 예약 출력은 브라우저 인쇄입니다. 운영 Docker·TLS 실행과 외부 제공자의 실시간 데이터 가용성은 별도 검증 대상입니다.
